Project Overview

One drone. Six engineering disciplines.

Aero Drop integrates flight control, GPS navigation, embedded firmware, distance sensing, communication and mechanical design into a single delivery-drone prototype.

🛰️

Autonomous Navigation

Waypoint missions planned in Mission Planner and flown by a Pixhawk 2.4.8 with NEO-8M GPS positioning.

📏

Local Obstacle Sensing

Three VL53L0X Time-of-Flight sensors measure clearance at the front, left and right of the aircraft.

🧠

Embedded Decision Logic

An ESP32 running FreeRTOS tasks evaluates distance thresholds and selects an avoidance response.

📡

MAVLink Telemetry

Supported messages and commands are exchanged between the ESP32 and the flight controller.

📦

Servo Payload Release

A servo-operated mechanism in the payload box releases the carried item at the delivery stage.

🌐

Live Web Dashboard

The ESP32 hosts a web page showing selected flight and sensor information, refreshed about every 500 ms.

Workflow

The five-step response loop

While the autopilot follows GPS waypoints, the embedded controller continuously runs this cycle.

Sensor Reading

Three VL53L0X Time-of-Flight sensors measure distance ahead and to both sides. The ESP32 collects readings continuously.

1

Obstacle Detection

Readings are compared against a defined distance threshold. A front reading below it indicates an obstacle in the flight path.

2

Path Adjustment

The controller compares side clearances and selects a response toward the side with more room, coordinating with the flight controller.

3

Path Verification

Sensor data is checked again to confirm the path ahead is clear before the normal mission resumes.

4

Mission Resumption

With the obstacle cleared, the aircraft returns to waypoint navigation and continues toward the delivery point.

🚧 Known Limitations

  • Three sensors cover three directions only — not full 360° detection.
  • ToF sensors have limited range and can be affected by surface and lighting.
  • Maximum payload and delivery accuracy are not yet verified.
  • Measured performance needs repeated, documented trials.
  • The web dashboard is for monitoring, not safety-critical control.

🛡️ Safety Considerations

  • Follow local drone laws and operate only in an authorized area.
  • Keep people clear of the flight path and release area.
  • Use safe LiPo charging, storage and handling; secure battery and payload.
  • Verify pilot takeover and failsafes before every flight.
  • Never test avoidance near people, roads or buildings.
What's Next

Engineering roadmap

Planned directions to make the system more capable, more reliable and better documented.

📡 Sensing & Autonomy

  • Expand obstacle coverage with suitable additional sensing hardware
  • Improve filtering and validity checks for distance readings
  • Investigate more advanced mapping and path planning
  • Improve command verification and mission recovery

🛡️ Reliability & Safety

  • Define explicit safe states for avoidance failures
  • Add command timeouts and communication-loss handling
  • Log sensor data and control decisions with timestamps
  • Automated tests for sensor processing and decision logic

📊 Validation & Release

  • Measure maximum payload and endurance systematically
  • Evaluate delivery deviation over repeated trials
  • Record exact firmware, libraries and build settings
  • Establish a repeatable build, test and release process

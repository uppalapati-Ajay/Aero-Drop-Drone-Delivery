# Contributing

1. Keep changes scoped and explain the reason for each change.
2. Do not commit Wi-Fi passwords, API keys, private telemetry, or personal data.
3. Include board, framework, library, and firmware versions for code changes.
4. Document pin assignments and electrical assumptions alongside firmware.
5. Test sensor logic on the bench before flight testing.
6. Include reproducible test steps and honest outcomes.
7. Flight tests must be performed in a controlled, legally permitted area with a capable pilot and a safe means of taking over.
